# Hotel Recommender — 出差酒店推荐

## 目的

根据用户提供的出差目的地，实时搜索并推荐适合商务出行的酒店，以 HTML 页面形式输出，帮助用户快速做出决策。

## 触发场景

- 用户提到出差目的地（城市、地区或具体地点）
- 用户询问住哪家酒店、该选哪里住、出差住宿推荐
- 用户提供了出行时间或预算等偏好
- 用户追问某品牌（桔子、全季、亚朵等）在附近是否有门店

## 工作流程

### 第一步：明确需求

如果用户只给了目的地，先快速确认以下信息（可以合并成一句话问，不要逐条询问）：

- **价格区间**：经济/舒适/豪华（约 300 以下 / 300-600 / 600 以上，人民币/晚）
- **优先考虑**：靠近市中心、高铁站/机场、会展中心，还是客户公司附近
- **入住时间**：如果用户提到了具体日期就更好

如果用户没有提供，使用合理默认值：**舒适型（300-600元）、市中心区域**，并在推荐时说明默认假设。

### 第二步：实时搜索酒店信息

使用 `web_search` 工具搜索目的地的酒店信息。**至少执行 2 组搜索**，确保覆盖全面：

**第一组：综合搜索**（发现热门酒店）
```
"[城市] 出差商务酒店推荐 [年份]"
"[城市] [区域/地标] 附近酒店"
```

**第二组：品牌覆盖搜索**（避免遗漏知名连锁品牌在该区域的门店）
```
"[城市] [区域] 全季 桔子 亚朵 希尔顿欢朋 酒店"
"[城市] [区域] 华住 锦江 万豪 酒店"
```
目的：很多用户对特定品牌有偏好（如桔子、全季、亚朵），第一组搜索容易漏掉这些品牌门店，第二组专门补全。

如有必要，可追加搜索：
```
"[酒店名] 评价 点评 价格"
```

### 第三步：生成 HTML 推荐页面

搜索完成后，生成一个 HTML 文件，按以下结构组织推荐内容：

#### 页面结构

1. **顶部 Header**：标题（"预定[城市][区域]附近酒店"）+ 副标题（入住日期、区域说明）
2. **总览表格**：每维度一行，4列——维度标签、推荐酒店、参考价格、推荐理由
3. **维度卡片区域**：按维度分 section，每维度 2 家酒店卡片，卡片间用渐变分隔线隔开

#### 推荐维度（固定 4 个）

| 维度 | 侧重点 | 卡片边框色 |
|------|--------|-----------|
| 📍 位置最佳 | 离目标地点最近，出差效率最高 | 绿色系 |
| ✨ 品质体验 | 住得舒服有格调，设计感/口碑好 | 紫色系 |
| 🌍 国际品牌 | 全球连锁品质保障，积分体系划算 | 蓝色系 |
| 💰 性价比最优 | 预算友好但不住得差 | 黄色系 |

#### 卡片内容

每张酒店卡片包含：
- **图片区域**：使用 Unsplash 通用酒店/建筑类图片（搜索 `hotel`、`building`、`room` 等关键词），格式：`https://images.unsplash.com/photo-XXXXX?w=800&h=400&fit=crop`。如 Unsplash 图片无法获取，使用渐变色背景 + emoji 占位。
- **排名序号**：1 号用金色渐变背景，2 号用灰色背景
- **酒店名 + 评分**：评分用星级+数字（如 ★ 4.9 / 5.0）
- **价格**：右侧对齐，格式"¥XXX–XXX/晚"
- **一句话简介**：2-3 句话介绍酒店特色、位置、设施
- **推荐理由**：左蓝色边框卡片，含"推荐理由"标签 + 具体理由文字

#### 页面样式

- **深色主题**：背景 #0a0a0a，卡片背景 #141414，边框 #222
- **字体**：-apple-system, BlinkMacSystemFont, 'PingFang SC', 'Helvetica Neue', sans-serif
- **响应式**：移动端单列，640px+ 双列
- **交互**：卡片 hover 时 translateY(-2px) + 阴影增强
- **分隔线**：维度之间用 `linear-gradient(to right, transparent, #333, transparent)` 渐变线

### 第四步：给出总结建议

在 HTML 页面底部，添加简洁的 footer 提示：
- 价格仅供参考，实际以预订平台为准
- 周末/节假日房源紧张，建议尽快锁房
- 提供携程等平台的搜索链接

## 输出规范

- 输出格式：**HTML 文件**，使用 `write_to_file` 写入工作区，然后用 `preview_url` 展示
- 文件名：`hotel-[城市拼音]-[区域关键词].html`
- 语言：与用户保持一致（中文问则中文答）
- 态度：像一个有经验的差旅助理，给出有主见的建议，而不是罗列大量信息让用户自己判断

## 注意事项

- 价格仅供参考，实际以预订平台（携程、美团、飞猪等）为准
- 如搜索结果不够充分，可提示用户在哪些平台查看最新价格
- 对于不熟悉的小城市，优先推荐全国连锁品牌（如：万豪、希尔顿、华住旗下品牌、锦江、亚朵等），可靠性更高
- 对于大城市/热门商圈，务必覆盖多个品牌系列（华住：全季、桔子、桔子水晶、汉庭、美居；锦江：白玉兰、维也纳；亚朵；万豪：万枫、希尔顿欢朋等），避免只搜到一部分
- 用户追问某品牌是否有门店时，立即追加品牌专项搜索，并将结果补充到推荐页面
- 涉及出境出差时，注意提醒签证、语言、支付等实用信息
- OTA 网站（携程/美团/Booking）的酒店图片是动态加载且有防盗链，`web_fetch` 无法抓取；酒店图片使用 Unsplash 通用素材或渐变色占位

## 踩坑经验

- 综合搜索容易漏掉用户偏好的品牌门店（如桔子水晶），必须额外做品牌覆盖搜索
- OTA 网站图片无法通过 web_fetch 抓取（动态渲染+防盗链），不要浪费时间尝试
