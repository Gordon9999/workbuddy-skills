# 出差行程管理 · business-trip-planner

一套把一次出差行程做成可随身查看网页的工作流：以温润风格 HTML 呈现「行程 / 订单 / 清单」三件套，并托管到 GitHub Pages，手机随时能开。

**核心原则：用户只给骨架信息（日期、航班号、会面对象），其余（航站楼、时刻、天气、行李规则、酒店细节）由技能自查补齐；展示只留必要项，不写填充文案。**

## 一、何时使用

- 「做个出差行程管理」/「行程生成 HTML」/「订单确认页」/「天气行李清单」
- 「发布到 git」且目标是行程页（默认仓库 `Gordon9999/life`，目录 `us/`）

## 二、产物结构（每次出差一套，slug 用英文短横线，如 `us-aug-2026`）

| 文件 | 作用 |
|------|------|
| `trip-{slug}.html` | 行程页，主文件，`简单` + `详细` 两模式切换；发布时改名为 `index.html` |
| `orders-{slug}.html` | 订单确认页，与行程页互链，按出发日期排序 |
| `weather-luggage-{slug}.html` | 清单页：天气（按城市）+ 行李清单，行程页称其为「清单」并互链 |
| `trip-{slug}.md` | 源文件，沉淀原始行程与酒店订单，便于回溯 |

四文件同目录，互链用相对路径（`index.html` / `orders-...html` / `weather-luggage-...html`）。

## 三、温润风格 CSS 规范（三页共用）

- 底色 `#f7f2e9`，卡片/面板米白 `#fbf7ef`，次面板 `#f3ece0`
- 主点缀色（陶土）`#b0764f`；文字主色 `#3a332a`，弱色（muted）`#8a7d6b`
- 标题用衬线/宋体：`"Songti SC","Noto Serif SC",Georgia,serif`
- 圆角胶囊状态标签（✅已确认 / 待确认），圆角 12–14px
- 图标体系：`✈️` 航班 · `🏠`→改用 `聚会` · `🍽` 聚餐 · `💼` 拜访 · `🏨` 住宿
- 响应式：横排三栏在窄屏（≤640px）变竖排，手机友好

## 四、行程页规则（已固化，沿用）

1. **不写 D1-D9 标签**，日期 + 星期为主标识（如 `8/16 周日`）。
2. **分段**：每天按 `上午 / 下午 / 晚上` 三段；空时段直接写「空」，不写「机动/休整/复盘/总结」等填充文案。
3. **一天一行活动**：一次活动一行，无填充描述。
4. **图标强化**：航班、聚会、聚餐、拜访用对应小图标；只列有活动的项。
5. **两模式**：
   - `简单` = 横版日卡片：左边日期+星期+🏨住宿（如 `Arlo Midtown ✅`），右边 上午/下午/晚上 三栏；含航班时刻、接机人等细节。
   - `详细` = 原样展开，末尾单独列「待确认」清单。
   - **待确认只在「详细」模式出现**，简单模式不展示。
6. **周起始为周一**：用分隔线（如 `8/17 – 8/23` / `8/24 –`）体现分周。
7. **航班约定**：用户只给「日期 + 航班号」，其余（航站楼、机型、起飞/落地时刻、晚点）由技能自查，不烦用户。
8. 模式切换用纯 JS（`onclick` 切 `hide` 类），无外部依赖。

## 五、订单页规则

1. **按出发日期排序**：机票在前、酒店插进对应日期之间（如 MU587 → Arlo → Marriott → AA149）。
2. **隐私打码**（页面是公开的 GitHub Pages，必须做）：
   - 删除「联系手机」「联系邮箱」行
   - 护照号只显示后 4 位（`******35`）
   - 不暴露完整证件号
3. 字段：订单号、乘机人、票号、PNR/航司预订号、行李额、实付金额、状态。
4. 与行程页互链（顶部「返回行程」）。

## 六、清单页规则

1. **天气不列每天**，按城市分块：只写该城市在行程覆盖日期的「温度情况 + 建议穿衣」。
   - 例：纽约（8/16–18）湿热 20–30°C，短袖+薄外套；湾区（8/18–24）SF 凉 14–21°C 多雾风大、南湾暖 16–32°C，短袖+薄外套最稳。
2. **行李只列必须项**（用户明确去过的：伞不带、常用药不带、名片不带、充电宝不带、漫游不带、鞋不带、伴手礼不带）。每次按用户最新指令增删，不要凭空补回。
3. **箱子尺寸**记进行李规定（如 `RIMOWA Sleeve 55×39×23`，登机箱）。
4. **勾选存档用 localStorage，key 按条目文本**（不是序号），避免删项后勾选串位：
   ```js
   var boxes = document.querySelectorAll('.ck input');
   boxes.forEach(function(b){
     var k='pkg-'+b.nextElementSibling.textContent.trim();
     if(localStorage.getItem(k)==='1') b.checked=true;
     b.addEventListener('change',function(){localStorage.setItem(k,b.checked?'1':'0')});
   });
   ```
5. 随身宝贝（双币卡、双眼镜盒等）单列，永远随身。

## 七、GitHub 发布（life 仓库 / us 目录）

**本机限制**：`git push` 不可用（代理隧道 502 / 直连 443 被墙）。必须走 **GitHub Contents API**：

1. 仓库 `Gordon9999/life` 已建，GitHub Pages 已开（地址 `https://gordon9999.github.io/life/us/`）。
2. 目录名 `us/`，行程主文件上传为 `us/index.html`（用户访问目录即直出）。
3. 上传工具：`scripts/put_life.py <本地文件> <远程路径> [<本地> <远程> ...]`（**本地/云端双模式自动判别**）
   - **token 取用顺序**：环境变量 `GH_TOKEN` / `GITHUB_TOKEN`（云端沙箱模式）→ macOS `git credential fill` 钥匙串（本地模式）
   - **代理**：云端模式直连 api.github.com 免代理；本地模式自动检测动态端口 `scutil --proxy | grep HTTPPort`，走 `curl -x http://127.0.0.1:<port>`
   - 带 token 的 PUT 可能 302，curl 已加 `-L` 跟随
   - 需带旧 `sha`（GET 取 sha 再 PUT）；新文件无 sha
4. 每次修改后，把变更的 `index.html` / `orders-*.html` / `weather-luggage-*.html` / `*.md` 一并重新上传覆盖。

## 八、关键约定速查（用户习惯）

- 航班信息：只给日期+号，其余自查。
- 「家聚会」统一称「聚会」。
- 旅行相关提示要简短，不要长篇汇报；命令→动作→结果。
- 行程变动随时口头说，技能更新对应文件并同步 GitHub。
- 行李「只写必须项」，删项后不自行补回，除非用户要求。

## 九、随附脚本

`scripts/put_life.py` — 把本地文件 PUT 到 `Gordon9999/life/<远程路径>`，自动处理代理端口、token、sha。token 优先 `GH_TOKEN`/`GITHUB_TOKEN` 环境变量（云端沙箱模式直连免代理），否则回退本地 git credential + scutil 动态代理。

## 十、云端模式运行指南（多机 / 无本地参与）

用户诉求：**云端修改**（不是云端发布）——几台电脑都能改发行程，本地零参与。WorkBuddy 支持**云端沙箱模式**（agent 跑腾讯云隔离沙箱，本地只发指令收结果，关机照跑；另有 Claw 远程模式 / 微信小程序云端模式）。

关键事实与落地步骤：

1. **云端沙箱数据任务后自动删除、不持久**——改完的行程必须推外部持久存储，即 `Gordon9999/life` 仓库（Pages 自动发布）。云端 agent 改完文件后用 `put_life.py` 上传即可，产物持久在 GitHub。
2. **云端无本地钥匙串**——token 必须通过环境变量 `GH_TOKEN` 传入云端运行环境（在客户端/云端的任务配置里设置，或由平台注入）。`put_life.py` 已支持该模式。
3. **执行流程**（云端 agent 收到指令后）：
   - 用 GitHub Contents API 拉取 `us/index.html`、`orders-*.html`、`weather-luggage-*.html` 最新内容（GET，带 token）
   - 按本 skill 的行程/订单/清单规则修改
   - `put_life.py` 推回（或 curl PUT 带 sha），Pages 1–2 分钟自动刷新
4. **本地 ↔ 云端无缝**：同一份 skill 与脚本，本地跑自动用钥匙串+代理，云端跑自动用 `GH_TOKEN`+直连，无需两份配置。
5. **切换入口在客户端**：创建任务时选「云端沙箱」运行模式（agent 无法自己切），把 `GH_TOKEN` 配进云端环境后下发指令即可。
