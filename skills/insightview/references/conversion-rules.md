# 长文 ↔ 推文转换规则

## 一、长文转推文

### 核心原则

- 保持六大板块结构不变（推文模式将「一句话总结」提前到最前面）
- 长文是完整的信息提取结果，推文是长文的精简表达
- **绝不直接从原文生成推文**，必须基于已生成的长文进行改写

### 转换步骤

1. **板块映射**：将长文的六大板块直接映射为推文的板块结构
   - 📌 一句话总结 → 提前到推文串最前面
   - 📦 公司角度 → 对应板块
   - 🧩 产品角度 → 对应板块
   - 🏗️ 组织角度 → 对应板块
   - 👤 访谈人背景 → 对应板块（附录）
   - 💡 核心观点 → 对应板块（附录）

2. **信息点拆分**：将长文的每个段落/信息点拆成多条推文
   - 每条推文聚焦一个子主题
   - 推文标题用「推 N · [主题标题]」格式
   - N 为连续编号，不按板块重置

3. **语言风格转换**：
   - 长句拆成短句
   - 一段 2-4 句，表达完一个意思后换行
   - 口语化但保留全部信息
   - 用 `<p>` 标签包裹每一段

4. **高亮标注**：核心概念/关键数据/专有名词用绿色高亮
   - 使用 `<span class="highlight">关键词</span>`
   - 每条推文 1-3 个高亮

### 示例

长文段落：
> Decagon 成立于2023年，用两年时间从零到45亿美元估值。其核心差异化优势是AOPs（Agent Operating Procedures），让CX团队用自然语言配置AI Agent，而非依赖专业服务团队。目前90%的工作流运行在开源模型上，展现出极强的技术自主能力。

转换为推文：

```html
<div class="tweet">
    <div class="tweet-label">推 1 · 从零到 45 亿美元的两年</div>
    <div class="tweet-body">
        <p>Decagon 用两年时间从零到 <span class="highlight">45 亿美元估值</span>。</p>
        <p>核心差异化是 <span class="highlight">AOPs</span>——让 CX 团队用自然语言配置 AI Agent，而非依赖专业服务。</p>
        <p>90% 工作流运行在开源模型上。</p>
    </div>
</div>
```

## 二、推文转长文

### 核心原则

- 将推文串还原为结构化长文
- 恢复完整上下文和逻辑连接
- 推文中的口语化表达可适当书面化，但保留全部信息

### 转换步骤

1. **推文归集**：按板块将推文分组
2. **信息合并**：将同一板块内的推文合并为连贯的段落
   - 相邻推文的内容合并为一段
   - 添加过渡词使逻辑通顺
   - 恢复被拆分的长句
3. **结构化输出**：按六大板块结构输出 Markdown 格式长文
4. **信息校验**：对比推文内容，确保无信息遗漏

### 格式要求

- 输出格式：Markdown
- 板块标题：使用 `##` 级别标题
- 板块内段落：使用普通段落，不加额外标题
- 关键概念可加粗，但不使用绿色高亮（高亮仅用于 HTML 推文模式）

## 三、质量检查清单

### 长文质量检查

- [ ] 六大板块结构完整
- [ ] 信息提取完整，无遗漏
- [ ] 逻辑清晰，段落连贯
- [ ] 关键数据和专有名词准确

### 推文质量检查

- [ ] 推文编号连续，不按板块重置
- [ ] 每条推文聚焦一个子主题
- [ ] 每段 2-4 句，意思完整后换行
- [ ] 绿色高亮每条 1-3 个
- [ ] 口语化但信息完整
- [ ] 推文数量符合要求（主报告 12-16 条，附录 16-23 条）

### 转换一致性检查

- [ ] 长文与推文信息一致，无增减
- [ ] 板块结构对应
- [ ] 关键数据和概念表述一致
