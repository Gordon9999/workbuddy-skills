# 批量生成策略

## 一、首次生成

### 生成内容

首次生成时，输出：
1. **主报告**（`index.html`）：汇总所有素材的核心洞察，12-16 条推文
2. **第一批高质量篇目附录**：为筛选出的高质量篇目生成单独的附录 HTML

### 其他附录

未生成的附录在索引中标记「待生成」状态。

## 二、高质量篇目筛选标准

按以下优先级筛选首批生成的篇目：

### 优先级 1：创始人/CEO 深度访谈
- 创始人或 CEO 的深度对话
- 涉及公司战略、愿景、发展历程
- 信息密度高，有独特洞察

### 优先级 2：核心技术或产品发布
- 重要产品发布或技术突破
- 涉及核心技术架构、差异化能力
- 有具体的技术细节和数据

### 优先级 3：战略层面内容
- 融资、并购、重大合作
- 市场策略、竞争格局分析
- 组织架构和人才策略

### 优先级 4：内容完整度高
- 素材信息丰富，覆盖多个维度
- 有具体案例和数据支撑
- 逻辑清晰，易于结构化提取

## 三、追加生成

### 触发方式

- 用户说「追加附录 N」→ 生成指定编号的附录
- 用户说「全部生成」→ 生成所有待生成的附录

### 追加流程

1. 读取对应篇目的长文（如未生成长文，先执行长文生成步骤）
2. 将长文改写为 xInsightView 推文串
3. 生成对应的附录 HTML
4. 更新主报告索引：将该附录从「待生成」改为「已生成」并可点击跳转

## 四、HTML 文件组织

### 文件命名

| 文件 | 内容 |
|------|------|
| `index.html` | 主报告 + 附录索引 |
| `p1.html` | 附录 1（第一篇高质量篇目） |
| `p2.html` | 附录 2（第二篇高质量篇目） |
| ... | 以此类推 |

### 主报告与附录的关系

- 主报告（`index.html`）包含所有素材的综合洞察 + 附录索引
- 每篇附录（`pN.html`）是对单篇素材的详细推文串
- 附录索引在主报告页面底部，已生成的用可点击链接 + 绿色徽章

### 分批发文策略

- 首次发文：主报告 + 第一批高质量附录
- 追加发文：按用户请求逐篇或全部追加
- 每次追加后更新主报告索引状态

## 五、生成顺序

1. 读取所有已上传素材，确认主题
2. 对每篇素材执行长文生成（步骤 B）
3. 筛选高质量篇目
4. 生成主报告 HTML（综合所有素材的核心洞察）
5. 为高质量篇目生成附录 HTML
6. 更新主报告附录索引（已生成 + 待生成）
7. 等待用户追加请求
