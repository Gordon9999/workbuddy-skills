# 书写风格详细规范

## 一、句子层面

### 规则

1. **每句不超过 25 个字**。超过就拆。
2. **口语化**。像说话，不像写公文。
3. **主谓宾直接说**。不用「通过…实现…」这种冗长结构。
4. **禁止从句套从句**。一句话只说一件事。

### 正确示例

> 他们用大模型把客服流程跑通了。
> 运营成本降下来了，用户满意度也上去了。
> Decagon 两年做到 45 亿美元估值。

### 错误示例（禁止）

> 该公司通过引入先进的自然语言处理技术和大规模语言模型，实现了客户服务流程的全面自动化，从而显著降低了运营成本并提升了用户满意度。

**为什么错**：一句话 56 个字，从句套从句，「通过…实现了…从而…」三层嵌套，信息被句式淹没。

## 二、段落层面

### 规则

1. **每段 2-3 句**。说完一个意思就换行。
2. **一段只说一件事**。不要把多个主题混在一段里。
3. **段间有逻辑**。上段结尾和下段开头要有衔接，但不用写过渡句。

### 正确示例

```html
<p>Decagon 的核心差异化是 <span class="highlight">AOPs</span>。</p>
<p>这让 CX 团队能用自然语言配置 AI Agent，不依赖工程师。</p>
<p>90% 的工作流跑在开源模型上。</p>
```

**为什么对**：每段一句话，三个信息点清晰排列，读者扫一眼就能抓住重点。

### 错误示例（禁止）

```html
<p>Decagon 的核心差异化是 AOPs，这让 CX 团队能用自然语言配置 AI Agent，不依赖工程师，同时 90% 的工作流跑在开源模型上，大幅降低了运营成本。</p>
```

**为什么错**：四层信息塞在一个 `<p>` 里，读者需要读完整句才能理解，无法快速扫读。

## 三、用词层面

### 禁止词汇表

| 禁止 | 替代 |
|------|------|
| 赋能 | 帮到 / 支持 |
| 抓手 | 切入点 / 方法 |
| 闭环 | 跑通 / 完成 |
| 生态 | 上下游 / 合作伙伴 |
| 颠覆 | 改变 / 替代 |
| 沉淀 | 积累 |
| 对齐 | 确认 / 统一 |
| 颗粒度 | 细节程度 |
| 复盘 | 回顾 / 总结 |
| 心智 | 认知 / 印象 |
| not only...but also | 直接分两句说 |

### 数据表达规则

- **必须具体**：写「45 亿美元」不写「数十亿美元」
- **必须准确**：写「90%」不写「绝大部分」
- **带单位**：写「3 个月」不写「一段时间」
- **带来源**：如果是引用数据，注明出处

## 四、标题层面（FT 头版风格）

### FT 标题特征

FT（Financial Times）头版标题的核心是：**像报纸编辑写的，不像自媒体写的**。

1. **简洁**：中文 5-15 个字，英文 5-12 个词
2. **陈述**：直接说事实或判断，不搞噱头
3. **可带角度**：用冒号或破折号分隔主题和观点
4. **权威**：语气笃定，不用「可能」「或许」

### 标题类型与示例

| 类型 | 示例 |
|------|------|
| 直述型 | AI 客服赛道跑出一个 45 亿美元的玩家 |
| 分析型 | Decagon：用自然语言重塑客服 Agent |
| 判断型 | 开源模型撑起了一家 45 亿美元的公司 |
| 问句型 | 客服 AI 真的能替代 Salesforce 吗 |

### 生成标题时的规则

- **必须给出 2-3 个选项**，覆盖不同角度
- 选项之间风格要不同（不要三个都是直述型）
- 用户选定后才开始写正文
- 如果用户已经给了标题，直接使用

### Kicker（分类标签）

标题上方的小标签，2-4 个字：
- 行业观察 / 产品分析 / 组织管理 / 技术解读 / 市场趋势 / 人物访谈
- 也可自定义，但必须简短

### Standfirst（导语）

标题下方的一句话概括：
- 1-2 句，不超过 50 字
- 点出文章最核心的信息或判断
- 不是标题的重复，是标题的延伸

## 五、高亮使用规范

### 规则

1. **只高亮关键信息**：核心概念、关键数据、专有名词
2. **每段 0-2 个**：不宜过多，多了等于没高亮
3. **高亮词要短**：2-6 个字最佳，不超过 10 个字
4. **用 `<span class="highlight">` 标签**

### 正确示例

```html
<p>核心差异化是 <span class="highlight">AOPs</span>——用自然语言配置 Agent。</p>
<p>估值到了 <span class="highlight">45 亿美元</span>。</p>
```

### 错误示例（禁止）

```html
<p><span class="highlight">Decagon 用两年时间从零到 45 亿美元估值</span>，核心差异化是 AOPs。</p>
```

**为什么错**：高亮了一整句话，失去重点提示作用。

## 六、尾部信息规范

### 必备三要素

| 字段 | 格式 | 说明 |
|------|------|------|
| 生成日期 | YYYY-MM-DD | 当前日期 |
| 来源 | 自由文本 | 素材来源说明 |
| LLM 标注 | 固定文案 | 使用了 LLM 改写时必须注明 |

### LLM 标注规则

- **使用 LLM 改写/重写/润色**：标注「本文由 AI 辅助改写，原始内容来自 {{来源}}」
- **纯排版未改内容**：不标注 LLM
- **LLM 从零生成**：标注「本文由 AI 生成」
- **人写 + AI 润色**：标注「本文由作者撰写，AI 辅助润色」

### 尾部 HTML 示例

```html
<div class="footer">
    <div class="footer-meta">生成日期：2026-08-10</div>
    <div class="footer-meta">来源：用户提供文本</div>
    <div class="footer-meta">本文由 AI 辅助改写，原始内容来自用户提供的访谈笔记</div>
</div>
```
